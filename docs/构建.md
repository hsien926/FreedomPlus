# 构建指南

本文档描述如何从源码构建 FreedomPlus。命令已在 **Windows + PowerShell** 与 **JDK 17 + Android SDK 34** 环境实测通过。

---

## 一、环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **17** | 必须 17；Kotlin 1.8.10 与 AGP 8.5.0 均要求 17 |
| Android SDK | 需含 `platforms;android-34`、`build-tools;34.0.0` | 六个模块都声明 `compileSdk 34` |
| Gradle | 8.7 ~ 8.9 | 工程 wrapper 声明 **8.9**；AGP 8.5.0 支持区间为 8.7~8.9 |
| 网络 | 首次构建需可访问 Maven 仓库 | 见下方「镜像源」 |

安装 Android SDK 34：

```bash
sdkmanager "platforms;android-34" "build-tools;34.0.0"
```

---

## 二、获取源码

```bash
git clone https://github.com/hsien926/FreedomPlus.git
cd FreedomPlus
```

### 关于 `ktutils/` 与 `xpler/`

这两个目录来自上游项目，在本仓库中**以普通目录形式直接纳入版本控制**（不是 git submodule），因此 `git clone` 一条命令即可拿到完整可构建的源码树，无需 `--recursive`。

| 路径 | 来源 | 在本仓库中的改动 |
|---|---|---|
| `ktutils/` | [GangJust/ktutils](https://github.com/GangJust/ktutils) | 无（内容与上游一致，包名保持 `com.freegang.ktutils`） |
| `xpler/` | [ThatWorld/xpler](https://github.com/ThatWorld/xpler) | `build.gradle.kts`：移除发布与签名插件，并复用版本目录中的 Xposed API 82 编译期依赖；不再引用已移除的本地 API JAR |

这样做是为了避免子模块在 clone 时未初始化导致的构建失败，代价是与上游的同步需要手动进行（对比上游后再提交差异）。

## 三、配置本地环境

### 3.1 SDK 路径

在工程根目录创建 `local.properties`（已在 `.gitignore` 中忽略）：

```properties
sdk.dir=D\:\\Tools\\android-sdk
```

> Windows 路径中的反斜杠需要转义，或直接使用正斜杠：`sdk.dir=D:/Android/Sdk`。

### 3.2 环境变量

PowerShell 示例：

```powershell
$env:JAVA_HOME      = 'D:\Tools\jdk-17'
$env:ANDROID_HOME   = 'D:\Tools\android-sdk'
$env:ANDROID_SDK_ROOT = 'D:\Tools\android-sdk'
```

Bash 示例：

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_SDK_ROOT=$ANDROID_HOME
```

### 3.3 镜像源（可选）

`settings.gradle` 已预置阿里云公共镜像。若所在网络访问 `google()` / `mavenCentral()` 缓慢，镜像会优先生效；若需完全离线构建，可预热 Gradle 缓存后加 `--offline`。

## 四、构建

### 4.1 调试包

```bash
./gradlew assembleDebug
```

Windows：

```powershell
.\gradlew.bat assembleDebug
```

产物：`app/build/outputs/apk/debug/freedom+_1.3.12.apk`

调试包不混淆、不压缩资源，体积约 12 MB，适合对照源码排查问题。它使用 Android 默认调试证书签名，**与 release 包不能互相覆盖安装**。

### 4.2 发布包

发布包需要签名配置。在工程根目录创建 `keystore.properties`（已在 `.gitignore` 中忽略）：

```properties
storeFile=freedom-release.jks
storePassword=<你的密钥库口令>
keyAlias=freedom
keyPassword=<你的密钥口令>
```

`storeFile` 支持相对工程根目录的相对路径，也支持绝对路径。

```bash
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/freedom+_1.3.12.apk`

**不配置 `keystore.properties` 时**，release 变体仍可正常构建，但产物未签名，无法直接安装（可手动 `apksigner sign`）。

### 4.3 生成新密钥

如果你是从零开始（而不是接手维护本项目的发布线）：

```bash
keytool -genkeypair -v \
  -keystore freedom-release.jks \
  -alias freedom \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass <库口令> -keypass <密钥口令> \
  -dname "CN=YourName, OU=Local, O=LocalBuild, L=Local, ST=Local, C=CN"
```

> **注意**：Android 只允许**签名相同**的 APK 覆盖安装。一旦对外发布过某个密钥签名的版本，后续所有版本都必须沿用同一密钥，否则用户升级会被系统拒绝（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。请务必备份密钥文件。

## 五、验证产物

### 5.1 基本信息

```bash
# 包名 / 版本号
aapt dump badging app/build/outputs/apk/release/freedom+_1.3.12.apk | head -1

# 预期输出
# package: name='io.github.fplus' versionCode='148' versionName='1.3.12'
```

### 5.2 签名

```bash
apksigner verify --print-certs -v app/build/outputs/apk/release/freedom+_1.3.12.apk
```

预期看到 `Verifies`、`Verified using v2 scheme: true`，以及你的证书指纹。

### 5.3 混淆后功能是否存活

release 包做了字典混淆（`app/dic.txt`），但以下两项必须存活，否则模块不会被框架加载：

```bash
# 入口类必须保持原名
baksmali disassemble app/build/outputs/apk/release/freedom+_1.3.12.apk -o out
ls out/io/github/fplus/HookInit.smali      # 必须存在

# 入口声明
unzip -p app/build/outputs/apk/release/freedom+_1.3.12.apk assets/xposed_init
# 预期输出：io.github.fplus.HookInit
```

`app/proguard-rules.pro` 中的 `-keep class io.github.fplus.HookInit` 与 `-keepattributes *Annotation*` 是保证这一点的关键规则，**不要删除**。

## 六、常见问题

**构建时报找不到 `platforms;android-34`**
六个模块都声明了 `compileSdk 34`。用 `sdkmanager` 补装即可，无需改动工程配置。

**`Execution failed for task ':app:compileDebugKotlin'`**
优先确认 JDK 是 17。JDK 21 与 Kotlin 1.8.10 不兼容。

**构建通过但模块不生效**
先确认设备上装了 64 位抖音，且 LSPosed 作用域已勾选。本机 logcat 中 TAG `Freedom+` 会输出各拦截组与 matcher 的命中结果：

```bash
adb logcat -s Freedom+
```

**改了 `DexkitBuilder` 里的匹配规则却不生效**
DexKit 有结果缓存。修改任何 matcher 后必须同步递增 `DouYinMain.kt` 中的 `version`（当前为 `33`），否则会读到上一次的搜索结果。

## 七、GitHub Actions 合并前测试与编译

仓库工作流在 `pull_request`、推送 `main` 和手动运行时执行，使用 Temurin JDK 17、Android SDK 34 / build-tools 34.0.0、Gradle 8.9。权限为 `contents: read`，不读取正式签名 Secrets，不创建 GitHub Release，不因标签推送自动发布。

### 7.1 执行与校验

1. 执行 Python 校验器回归与全部核心 JVM 单元测试。
2. 编译 Debug 与未签名 Release，后者只用于编译、R8 和 DEX 验证，不能当作正式安装包。
3. 断言实际 APK 包名、versionCode、versionName 及包内 `assets/version`，不只打印 aapt 输出。
4. 验证 Debug 签名，确认 CI Release 未签名。
5. 检查包内 Xposed 入口声明，以及 DEX 中真正的入口方法、应用侧和系统侧高刷回调执行体。校验器使用 Androguard 4.1.4，仅为构建检查依赖，不进入 APK。
6. 上传测试结果、验证 JSON、APK 与 Release 映射，摘要包含 SHA-256。

### 7.2 开发版本标识

CI 使用当前提交 SHA 的前十二位追加开发后缀，例如 `1.3.12.abcdef012345`；`versionCode` 仍由工程配置读取，当前为 148。本地不传后缀时仍为 `1.3.12`。

```bash
./gradlew :core:testDebugUnitTest :app:assembleDebug :app:assembleRelease
./gradlew :app:assembleDebug -PversionSuffix=abcdef012345
```

手动后缀兼容四至十二位小写十六进制，错误格式会在配置阶段失败。

### 7.3 取回产物与正式发布

Actions 运行页面可取回 `freedomplus-debug-*`、`freedomplus-release-unsigned-*` 和 `freedomplus-tests-*`。未签名 Release 不直接安装，Debug 也不覆盖固定签名的历史 Release。

正式发布继续使用本地既有密钥和发布验收流程。版本变更、签名、发布包替换、创建标签或 Release 都是独立操作；本工作流不自动完成这些步骤，也不要求上传密钥。
