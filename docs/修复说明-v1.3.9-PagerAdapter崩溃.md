# v1.3.9 PagerAdapter 崩溃修复

## Issue

- 仓库：`hsien926/FreedomPlus`
- Issue：[`#1 运行不到一分钟出错`](https://github.com/hsien926/FreedomPlus/issues/1)
- 反馈环境：Samsung SM-S9380 / Android 17 / 抖音 40.8.0（400800）/ arm64 / FreedomPlus 1.3.8（144）

## 现象

抖音运行约一分钟后进入模块崩溃页，核心异常为：

```text
java.lang.IllegalStateException:
The application's PagerAdapter changed the adapter's contents without calling
PagerAdapter#notifyDataSetChanged!
```

堆栈落在抖音与 `VerticalViewPager` 相关的测量、布局调用链。

## 根因

旧版 `HFeedAdFilter` 通过改写信息流 `AbstractFeedAdapter.getCount()` / `getItem()`，让 Pager 只看到过滤广告后的位置。这破坏了 PagerAdapter 的索引契约：

1. `VerticalViewPager.populate()` 会在 `notifyDataSetChanged()` 时保存当时的 `getCount()`，后续滚动回调再次调用 `populate()` 时要求数量保持不变；旧实现重复扫描动态窗口，可能从过滤后的 13 项变回原始 15 项。
2. 抖音的 `BaseListFragmentPanel` / `FollowFeedFragmentPanel` 会用 `getCount() == 0` 判断是否整表替换。Hook 改小计数会让宿主进入“替换但不 notify”的分支，使 ViewPager 保存的期望数量永久过期。
3. 旧实现只翻译了 `getItem()`，`getItemPosition()`、页面宽度和删除接口仍在原始索引空间工作，也会造成错位与重复重建。

## 修复

- 信息流过滤改到 Adapter 数据落表阶段：在 `LJLILLLLZI(List)` 与 `LJLJI(List, boolean)` 中剔除 `isAd` 项。
- 同步清理 Adapter 内与入参同源的平行列表，保证 `getCount()`、`getItem()` 和页面索引始终一致。
- `getCount()` 不再被改写，宿主原有 `notifyDataSetChanged()` 流程保持完整。
- 在崩溃容错中加入仅匹配 PagerAdapter 数量失配异常的兜底处理，并在下一帧通知 Adapter 刷新期望计数。
- 带插入位置或条数的增量接口不改入参，继续由 ViewHolder 层拦截兜底，避免破坏宿主索引计算。

> **2026-11 后续变更**：`VideoViewHolder` 层的拦截已下线 —— 它会留下 null 的 `FeedItemFragmentVM`，
> 切 tab 时抛 `getFeedAnimation()` NPE。现在改由 `HFeedAdNotifySweep` 在
> `notifyDataSetChanged()` 之前按引用剔除，仍然不改增量接口的入参；删不掉时直接放行。

## 验证

已完成 Debug / Release 构建与签名校验。

本修复已在**小米手机**完成真机验证。由于不同品牌的系统实现、权限策略和厂商定制可能不同，其他品牌手机需自行测试。
