# 构建指南

本文档描述如何从源码构建 FreedomPlus。命令已在 **Windows + PowerShell** 与 **JDK 17 + Android SDK 34** 环境实测通过。

---

## 一、环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **17** | 必须 17；Kotlin 1.8.10 与 AGP 8.5.0 均要求 17 |
| Android SDK | 需含 `platforms;android-34`、`build-tools;34.0.0` | 六个模块都声明 `compileSdk 34` |
| Gradle | 8.7 ~ 8.9 | 工程 wrapper 声明 **8.9**；AGP 8.5.0 支持区间为 8.7~8.9 |
| 网络 | 首次构建需可访问 Maven 仓库 | 见下方「镜像源」 |

安装 Android SDK 34：

```bash
sdkmanager "platforms;android-34" "build-tools;34.0.0"
```

---

## 二、获取源码

工程依赖两个子模块，**必须递归克隆**：

```bash
git clone --recursive https://github.com/hsien926/FreedomPlus.git
cd FreedomPlus
```

如果已经克隆但忘了 `--recursive`：

```bash
git submodule update --init --recursive
```

子模块说明：

| 路径 | 来源 |
|---|---|
| `ktutils/` | [GangJust/ktutils](https://github.com/GangJust/ktutils) |
| `xpler/` | [ThatWorld/xpler](https://github.com/ThatWorld/xpler) |

## 三、配置本地环境

### 3.1 SDK 路径

在工程根目录创建 `local.properties`（已在 `.gitignore` 中忽略）：

```properties
sdk.dir=D\:\\Android\\Sdk
```

> Windows 路径中的反斜杠需要转义，或直接使用正斜杠：`sdk.dir=D:/Android/Sdk`。

### 3.2 环境变量

PowerShell 示例：

```powershell
$env:JAVA_HOME      = 'D:\Tools\jdk-17'
$env:ANDROID_HOME   = 'D:\Tools\android-sdk'
$env:ANDROID_SDK_ROOT = 'D:\Tools\android-sdk'
```

Bash 示例：

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_SDK_ROOT=$ANDROID_HOME
```

### 3.3 镜像源（可选）

`settings.gradle` 已预置阿里云公共镜像。若所在网络访问 `google()` / `mavenCentral()` 缓慢，镜像会优先生效；若需完全离线构建，可预热 Gradle 缓存后加 `--offline`。

## 四、构建

### 4.1 调试包

```bash
./gradlew assembleDebug
```

Windows：

```powershell
.\gradlew.bat assembleDebug
```

产物：`app/build/outputs/apk/debug/freedom+_1.3.6.apk`

调试包不混淆、不压缩资源，体积约 12 MB，适合对照源码排查问题。它使用 Android 默认调试证书签名，**与 release 包不能互相覆盖安装**。

### 4.2 发布包

发布包需要签名配置。在工程根目录创建 `keystore.properties`（已在 `.gitignore` 中忽略）：

```properties
storeFile=freedom-release.jks
storePassword=<你的密钥库口令>
keyAlias=freedom
keyPassword=<你的密钥口令>
```

`storeFile` 支持相对工程根目录的相对路径，也支持绝对路径。

```bash
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/freedom+_1.3.6.apk`

**不配置 `keystore.properties` 时**，release 变体仍可正常构建，但产物未签名，无法直接安装（可手动 `apksigner sign`）。

### 4.3 生成新密钥

如果你是从零开始（而不是接手维护本项目的发布线）：

```bash
keytool -genkeypair -v \
  -keystore freedom-release.jks \
  -alias freedom \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass <库口令> -keypass <密钥口令> \
  -dname "CN=YourName, OU=Local, O=LocalBuild, L=Local, ST=Local, C=CN"
```

> **注意**：Android 只允许**签名相同**的 APK 覆盖安装。一旦对外发布过某个密钥签名的版本，后续所有版本都必须沿用同一密钥，否则用户升级会被系统拒绝（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。请务必备份密钥文件。

## 五、验证产物

### 5.1 基本信息

```bash
# 包名 / 版本号
aapt dump badging app/build/outputs/apk/release/freedom+_1.3.6.apk | head -1

# 预期输出
# package: name='io.github.fplus' versionCode='142' versionName='1.3.6' ...
```

### 5.2 签名

```bash
apksigner verify --print-certs -v app/build/outputs/apk/release/freedom+_1.3.6.apk
```

预期看到 `Verifies`、`Verified using v2 scheme: true`，以及你的证书指纹。

### 5.3 混淆后功能是否存活

release 包做了字典混淆（`app/dic.txt`），但以下两项必须存活，否则模块不会被框架加载：

```bash
# 入口类必须保持原名
baksmali disassemble app/build/outputs/apk/release/freedom+_1.3.6.apk -o out
ls out/io/github/fplus/HookInit.smali      # 必须存在

# 入口声明
unzip -p app/build/outputs/apk/release/freedom+_1.3.6.apk assets/xposed_init
# 预期输出：io.github.fplus.HookInit
```

`app/proguard-rules.pro` 中的 `-keep class io.github.fplus.HookInit` 与 `-keepattributes *Annotation*` 是保证这一点的关键规则，**不要删除**。

## 六、常见问题

**构建时报找不到 `platforms;android-34`**
六个模块都声明了 `compileSdk 34`。用 `sdkmanager` 补装即可，无需改动工程配置。

**`Execution failed for task ':app:compileDebugKotlin'`**
优先确认 JDK 是 17。JDK 21 与 Kotlin 1.8.10 不兼容。

**构建通过但模块不生效**
先确认设备上装了 64 位抖音，且 LSPosed 作用域已勾选。本机 logcat 中 TAG `Freedom+` 会输出各拦截组与 matcher 的命中结果：

```bash
adb logcat -s Freedom+
```

**改了 `DexkitBuilder` 里的匹配规则却不生效**
DexKit 有结果缓存。修改任何 matcher 后必须同步递增 `DouYinMain.kt` 中的 `version`（当前为 `33`），否则会读到上一次的搜索结果。
