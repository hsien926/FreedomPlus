# 构建指南

本文档描述如何从源码构建 FreedomPlus。命令已在 **Windows + PowerShell** 与 **JDK 17 + Android SDK 34** 环境实测通过。

---

## 一、环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **17** | 必须 17；Kotlin 1.8.10 与 AGP 8.5.0 均要求 17 |
| Android SDK | 需含 `platforms;android-34`、`build-tools;34.0.0` | 六个模块都声明 `compileSdk 34` |
| Gradle | 8.7 ~ 8.9 | 工程 wrapper 声明 **8.9**；AGP 8.5.0 支持区间为 8.7~8.9 |
| 网络 | 首次构建需可访问 Maven 仓库 | 见下方「镜像源」 |

安装 Android SDK 34：

```bash
sdkmanager "platforms;android-34" "build-tools;34.0.0"
```

---

## 二、获取源码

```bash
git clone https://github.com/hsien926/FreedomPlus.git
cd FreedomPlus
```

### 关于 `ktutils/` 与 `xpler/`

这两个目录来自上游项目，在本仓库中**以普通目录形式直接纳入版本控制**（不是 git submodule），因此 `git clone` 一条命令即可拿到完整可构建的源码树，无需 `--recursive`。

| 路径 | 来源 | 在本仓库中的改动 |
|---|---|---|
| `ktutils/` | [GangJust/ktutils](https://github.com/GangJust/ktutils) | 无（内容与上游一致，包名保持 `com.freegang.ktutils`） |
| `xpler/` | [ThatWorld/xpler](https://github.com/ThatWorld/xpler) | 仅 `build.gradle.kts`：移除 maven-publish 与 signing 插件，以支持本地直接构建 |

这样做是为了避免子模块在 clone 时未初始化导致的构建失败，代价是与上游的同步需要手动进行（对比上游后再提交差异）。

## 三、配置本地环境

### 3.1 SDK 路径

在工程根目录创建 `local.properties`（已在 `.gitignore` 中忽略）：

```properties
sdk.dir=D\:\\Android\\Sdk
```

> Windows 路径中的反斜杠需要转义，或直接使用正斜杠：`sdk.dir=D:/Android/Sdk`。

### 3.2 环境变量

PowerShell 示例：

```powershell
$env:JAVA_HOME      = 'D:\Tools\jdk-17'
$env:ANDROID_HOME   = 'D:\Tools\android-sdk'
$env:ANDROID_SDK_ROOT = 'D:\Tools\android-sdk'
```

Bash 示例：

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_SDK_ROOT=$ANDROID_HOME
```

### 3.3 镜像源（可选）

`settings.gradle` 已预置阿里云公共镜像。若所在网络访问 `google()` / `mavenCentral()` 缓慢，镜像会优先生效；若需完全离线构建，可预热 Gradle 缓存后加 `--offline`。

## 四、构建

### 4.1 调试包

```bash
./gradlew assembleDebug
```

Windows：

```powershell
.\gradlew.bat assembleDebug
```

产物：`app/build/outputs/apk/debug/freedom+_1.3.6.apk`

调试包不混淆、不压缩资源，体积约 12 MB，适合对照源码排查问题。它使用 Android 默认调试证书签名，**与 release 包不能互相覆盖安装**。

### 4.2 发布包

发布包需要签名配置。在工程根目录创建 `keystore.properties`（已在 `.gitignore` 中忽略）：

```properties
storeFile=freedom-release.jks
storePassword=<你的密钥库口令>
keyAlias=freedom
keyPassword=<你的密钥口令>
```

`storeFile` 支持相对工程根目录的相对路径，也支持绝对路径。

```bash
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/freedom+_1.3.6.apk`

**不配置 `keystore.properties` 时**，release 变体仍可正常构建，但产物未签名，无法直接安装（可手动 `apksigner sign`）。

### 4.3 生成新密钥

如果你是从零开始（而不是接手维护本项目的发布线）：

```bash
keytool -genkeypair -v \
  -keystore freedom-release.jks \
  -alias freedom \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass <库口令> -keypass <密钥口令> \
  -dname "CN=YourName, OU=Local, O=LocalBuild, L=Local, ST=Local, C=CN"
```

> **注意**：Android 只允许**签名相同**的 APK 覆盖安装。一旦对外发布过某个密钥签名的版本，后续所有版本都必须沿用同一密钥，否则用户升级会被系统拒绝（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。请务必备份密钥文件。

## 五、验证产物

### 5.1 基本信息

```bash
# 包名 / 版本号
aapt dump badging app/build/outputs/apk/release/freedom+_1.3.6.apk | head -1

# 预期输出
# package: name='io.github.fplus' versionCode='142' versionName='1.3.6' ...
```

### 5.2 签名

```bash
apksigner verify --print-certs -v app/build/outputs/apk/release/freedom+_1.3.6.apk
```

预期看到 `Verifies`、`Verified using v2 scheme: true`，以及你的证书指纹。

### 5.3 混淆后功能是否存活

release 包做了字典混淆（`app/dic.txt`），但以下两项必须存活，否则模块不会被框架加载：

```bash
# 入口类必须保持原名
baksmali disassemble app/build/outputs/apk/release/freedom+_1.3.6.apk -o out
ls out/io/github/fplus/HookInit.smali      # 必须存在

# 入口声明
unzip -p app/build/outputs/apk/release/freedom+_1.3.6.apk assets/xposed_init
# 预期输出：io.github.fplus.HookInit
```

`app/proguard-rules.pro` 中的 `-keep class io.github.fplus.HookInit` 与 `-keepattributes *Annotation*` 是保证这一点的关键规则，**不要删除**。

## 六、常见问题

**构建时报找不到 `platforms;android-34`**
六个模块都声明了 `compileSdk 34`。用 `sdkmanager` 补装即可，无需改动工程配置。

**`Execution failed for task ':app:compileDebugKotlin'`**
优先确认 JDK 是 17。JDK 21 与 Kotlin 1.8.10 不兼容。

**构建通过但模块不生效**
先确认设备上装了 64 位抖音，且 LSPosed 作用域已勾选。本机 logcat 中 TAG `Freedom+` 会输出各拦截组与 matcher 的命中结果：

```bash
adb logcat -s Freedom+
```

**改了 `DexkitBuilder` 里的匹配规则却不生效**
DexKit 有结果缓存。修改任何 matcher 后必须同步递增 `DouYinMain.kt` 中的 `version`（当前为 `33`），否则会读到上一次的搜索结果。

## 七、GitHub Actions 自动构建（无需本地环境）

仓库内置 [`.github/workflows/build.yml`](../.github/workflows/build.yml)，在 GitHub 托管的 runner 上完成与环境要求完全相同的构建：JDK 17（Temurin）、Android SDK 34、Gradle 8.9 wrapper，无需在本地安装任何工具链。

### 7.1 触发方式

| 触发 | 行为 |
|---|---|
| Actions 页面手动运行（`workflow_dispatch`） | 编译 debug + release，产物上传为 artifact；未配置密钥时 release 为未签名包 |
| 推送到 `main` | 同上 |
| 推送 `v*` 标签 | 同上，并额外创建 GitHub Release 挂载 release APK；**未配置签名密钥会直接失败** |

### 7.2 配置签名密钥（只需一次）

进入仓库 `Settings → Secrets and variables → Actions → New repository secret`，新建四个 Secret：

| Secret | 内容 |
|---|---|
| `KEYSTORE_BASE64` | 密钥库文件的 base64 单行字符串 |
| `KEYSTORE_STORE_PASSWORD` | 密钥库口令（对应 `keystore.properties` 的 `storePassword`） |
| `KEYSTORE_KEY_ALIAS` | 密钥别名（对应 `keyAlias`，本项目为 `freedom`） |
| `KEYSTORE_KEY_PASSWORD` | 密钥口令（对应 `keyPassword`） |

把 `freedom-release.jks` 转成 base64：

PowerShell：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("freedom-release.jks"))
```

Bash / Git Bash：

```bash
base64 -w 0 freedom-release.jks
```

CI 会在构建前把该字符串还原为工程根目录下的 `release.jks`，并生成 `keystore.properties`，随后 `app/build.gradle` 里已有的签名逻辑自动生效。密钥只存在于 runner 的临时工作区，不会进入仓库，也不会出现在日志中（Secrets 由 Actions 自动打码）。

> 密钥必须与历史发布版本一致，否则用户无法覆盖安装，参见 [4.3 生成新密钥](#43-生成新密钥)。

### 7.3 取回产物

- **普通构建**：Actions → 对应运行 → 页面底部 `Artifacts` → 下载 `freedomplus-debug` / `freedomplus-release`（release 附带 `mapping.txt`，用于还原崩溃堆栈）。
- **tag 构建**：Releases 页面直接下载 APK。

workflow 会自动校验以下三项，任一不通过即判失败：`aapt dump badging` 输出的包名与版本号、`apksigner verify` 的签名结果、`assets/xposed_init` 内容仍为 `io.github.fplus.HookInit`。每个 APK 的 SHA-256 会写入运行摘要，便于核对下载文件。

### 7.4 发布新版本

1. 修改 `app/build.gradle` 中的 `versionCode` 与 `versionName`；
2. 更新 `CHANGELOG.md`（以及 `docs/发布说明-*.md`）；
3. 推送后打标签，**标签名必须与 `versionName` 一致**（`versionName "1.3.9"` → `v1.3.9`），否则 workflow 会在编译前报错：

```bash
git tag v1.3.9
git push origin v1.3.9
```

### 7.5 未配置密钥时的行为

- 推送 `main` 或手动运行：构建仍然成功，但 release 是**未签名** APK，无法直接安装（可本地 `apksigner sign` 补签），仅用于验证源码可编译；
- 推送 tag：构建前置检查直接失败并提示补齐 Secrets，避免把不可安装的包发成正式版本。
