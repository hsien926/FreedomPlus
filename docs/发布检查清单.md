# 发布前检查清单

本文件是仓库维护者自用的发布流程清单，随仓库保留以便下一版本复用。

---

## 一、定版本号

- [ ] `app/build.gradle` 中 `versionCode` 递增（当前 `142`）、`versionName` 更新（当前 `1.3.6`）
- [ ] **不要重新生成签名密钥** —— Android 只允许同签名的 APK 覆盖安装，换密钥等于让所有用户卸载重装

## 二、更新内容

- [ ] `assets/update.txt` 顶部加新版本段落（模块内「长按更新日志」展示的就是它）
- [ ] `CHANGELOG.md` 加同样内容的条目
- [ ] `assets/versions.json` 加入本版实测适配的抖音版本号
- [ ] `README.md` 中的「适配版本」表更新实测基准

## 三、代码核对

- [ ] 搜索确认没有残留的硬编码外链：`GangJust`、`api.github.com`、第三方邮箱
- [ ] 若有改动 `core/.../DexkitBuilder.kt` 的 matcher，**必须同步递增 `DouYinMain.kt` 里的 `version`**
- [ ] 确认 `app/proguard-rules.pro` 中保留着 `-keep class io.github.fplus.HookInit` 与 `-keepattributes *Annotation*`

## 四、构建与验证

```powershell
$env:JAVA_HOME='<jdk-17>'
$env:ANDROID_HOME='<android-sdk>'
Set-Location '<repo>'
& gradle clean assembleRelease --no-daemon --console=plain
```

- [ ] `aapt dump badging` 确认包名 `io.github.fplus` 与版本号正确
- [ ] `apksigner verify --print-certs` 确认签名指纹与上一版**一致**
- [ ] release APK 反汇编后确认 `io/github/fplus/HookInit.smali` 仍为原始类名（未被混淆）
- [ ] `assets/xposed_init` 内容仍为 `io.github.fplus.HookInit`

## 五、发布

- [ ] 重命名 APK 为 `FreedomPlus-<版本号>-release.apk`
- [ ] 计算 SHA-256 写入 Release Notes
- [ ] 打 tag：`v<版本号>`
- [ ] 上传 APK 附件并发布

```powershell
Get-FileHash .\FreedomPlus-1.3.6-release.apk -Algorithm SHA256
```
