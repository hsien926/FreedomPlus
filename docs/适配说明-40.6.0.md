# 抖音 40.6.0 适配说明

本文件记录本项目针对抖音 40.6.0 所做的适配工作、遇到的问题及其根因。

**测试环境**：小米 M2102K1C / Android 17 / 抖音 40.6.0（64 位）/ LSPosed。

---

## 一、适配成果总览

| 指标 | 适配前 | 适配后 |
|---|---|---|
| 模块能否启动 | 抖音一启动即崩溃 | 正常启动 |
| 广告拦截 | 完全不执行 | 4 组真正接管 |
| DexKit matcher 命中 | 7 / 25 | 18 / 25 |

## 二、修掉的五个问题

### 1. 模块导致抖音一启动就崩溃

**现象**：启用模块后抖音无法启动，直接闪退。

**根因**：`HMainActivity` 中对代理类做了 `is MainTabStripScrollView` 这样的强制类型解析。`aweme` 模块是 `compileOnly` 的**代理壳**，只声明签名不打包实现，目标版本缺类时会抛 `NoClassDefFoundError`。而该调用位于主线程的 post 回调里，**无人捕获**，于是直接崩溃。

**修复**：四处高危的 `is` / `as` 改为类名比较；`initView` 整体加保护。

**配套规则**（写进代码注释，避免后人踩同一坑）：代理类一律用类名比较 + 反射，禁止 `is` / `as` / `::class`。

### 2. 广告拦截完全不执行

**现象**：日志显示拦截组已注册，但没有任何拦截动作。

**根因**：拦截组用 `NoneHook` 做占位。而 `HookEntity.init` 对 `NoneHook` 会直接 `return@runCatching`，**跳过了 `onInit()`** —— 也就是说 hook 从未真正注册。

**修复**：改用 `EmptyHook`。框架的官方注释里明确写了这个用法：占位但会执行 `onInit()`。

### 3. 小程序广告开关恒不生效（L1）

**现象**：无论怎么设置，小程序广告都拦不住。

**根因**：判定逻辑取 `args[0].toString()` 与广告类型名比对。但真实接口是：

```
isSupportAd(com.bytedance.bdp.appbase.context.BdpAppContext, com.tt.miniapp.ad.model.AdType)
```

第一个参数是**上下文对象**（`toString()` 出来是 `类名@哈希`），广告类型是**第二个参数的枚举对象**。拿 `args[0]` 去比对枚举名，恒不匹配。

**修复**：改为按参数逐个匹配 —— 枚举取 `name()`，其它类型退化为 `toString()`。

### 4. 小程序广告「跳过展示」（T5）恒不生效

**现象**：`T5` 组始终跳过。

**根因**：原实现依赖事件对象的 `LIZIZ` 字段判断状态，但实测 `AdCallback`（第二参）与 `MiniAppAdModel` / `GameAdModel` **都没有 `LIZIZ` 字段**；参数个数假设也与实际不符。

**修复**：重写为拦截 `operate*` 调用本身，并回调 `onFailure` 告知调用方。代价是 40.6.0 上方法名已混淆、匹配不到，**退化为不生效但不误伤**（明确记日志跳过），由广告类型总开关兜底。详见 [已知限制](已知限制.md)。

### 5. 侧边栏功能失效

**根因**：目标类被移动到 `sidebar.panel.ui` 子包下。

**修复**：匹配规则兼容新旧两条路径。

## 三、一个「改了却毫无效果」的坑

**现象**：修改 DexKit 的匹配规则后重新编译安装，行为完全没变。

**根因**：DexKit 有**结果缓存**。`cacheVersion` 不变时会直接读取上次的搜索结果 —— 包括搜索失败时缓存的字符串 `"null"`。所以「改了 matcher 却毫无效果」。

**修复**：递增 `cacheVersion`。

**强制约定**：**改动 `DexkitBuilder.kt` 里的任何 matcher，必须同步递增 `DouYinMain.kt` 中的 `version`**，否则改动不会生效。当前值为 `33`。

## 四、40.6.0 实测：实际接管的拦截组

```
host version=40.6.0 process=com.ss.android.ugc.aweme first=true 64bit=true
L1 hook isSupportAd(BdpAppContext, 0k0J)   → [group L1] ok
T1 hook 1Pq5.LIZ()                         → [group T1] ok
T3 hook AM(int,int,int)                    → [group T3] ok
L2 block InterstitialAdFactory.create(3)   → [group L2-interstitial] ok
L2 hook createRewardVideoAdFragment        → [group L2-reward] ok
T5-miniapp: no operate* method, skipped    → 见「已知限制」第二条
```

覆盖范围：**小程序广告、小游戏广告、激励视频、插屏**。

**不含**：信息流广告（见 [已知限制](已知限制.md) 第一条）、开屏广告。

### 最稳的一处设计

```
T1 hook 1Pq5.LIZ()
```

这是广告解析计时功能。它走 `parserField.type` **运行时取类型**，不写死解析器类名。该混淆名在 38.7.0 时是 `1DN2`、40.6.0 变成 `1Pq5`，功能始终不受影响。**凡是不写死混淆名的锚点，在版本漂移中都能活下来。**

## 五、信息流广告拦截的实现方式

原上游的信息流过滤链路（`recommendFeedFetchPresenter` 等）在 40.6.0 **整体不存在** —— 相关类已移除，持有 `FeedItemList` 的 55 个类里没有一个包含 `onSuccess`，`items` 字段也没有可 hook 的写入点。

因此本项目改用 **adapter / ViewHolder 层**重新实现。真机确认 `VideoViewHolder.bind` 是主 feed 的绑定入口（累计触发 150+ 次），在它前置拦截即可阻断广告项上屏。

三个入口各自挂了拦截器（可玩广告的 `bind` 是 final 重写，必须单独挂）：

| 目标类 | 覆盖 |
|---|---|
| `VideoViewHolder` | 普通视频项 |
| `PlayableVideoViewHolder` | 可玩广告 |
| `InteractivePlayableVideoViewHolder` | 互动可玩广告 |

判定依据 `Aweme.isAd`（序列化名 `is_ads`），已通过字节码确认其取值语义。

## 七、核对抖音内部类时的经验

以下几条来自实际核对过程，对后续适配有参考价值：

**方法若定义在父类，hook 会静默失效。** xpler 只检索目标类的 `declaredMethods`。抖音把方法上移到父类时，hook 就绑不上了，且不报错。

**`@OnBefore` / `@OnAfter` 写在基类里无效。** xpler 只扫 `this::class.java.declaredMethods`，注解方法必须写在具体子类中。

**`usingStrings` 匹配的是「类内引用」而不是「字符串池中存在」。** 字符串存在于 dex 字符串池，并不代表有类引用它。实测 `MainBottomTabView` 字符串在池中（3 个 dex 命中），但**没有任何类的字节码引用它**，对应的匹配规则必然失败。判断特征是否可用，必须搜 `const-string` 引用。

**`dalvik.annotation.Signature` 注解在 40.6.0 实例数为 0。** 依赖字段注解做匹配的路径整体失效。40.6.0 的稳定锚点是**未混淆的 getter / setter 组合**。

**按类名搜不到 ≠ 类被移除。** 类可能只是被混淆。实测 `CommentColorMode` 在 40.6.0 变成 `LX/0dQI;`（枚举常量 `MODE_LIGHT` / `MODE_DARK` 完好），按原名搜自然「缺失」，实际功能正常。凡是「某类型缺失」的结论都要再确认一次。

**Windows 下解析 dex 要注意文件名大小写。** 同名类在不同 dex 中可能存在大小写不同的路径（`LX/1BRF` / `LX/1bRF` / `LX/1BrF`），解压到同一目录树时会被 Windows 当作同一文件互相覆盖、内容丢失。类名判定必须直接解析 DEX，不能依赖解压后的文件名。

**搜 dex 字符串要用 UTF-8 解码 + 尾部 NUL 边界判定。** dex 字符串池的格式是 `[长度][MUTF-8 串][0x00]`，字符串前面是长度字节而非 NUL。用 latin1 解码会把多字节中文拆散，导致搜中文永远落空（假阴性）；用纯子串匹配则会让 `click_hea` 被 `click_head` 命中（假阳性）。只能用**尾部 NUL** 判定独立项。
