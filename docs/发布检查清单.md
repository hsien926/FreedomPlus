# 发布前检查清单

当前发布基准：**FreedomPlus v1.3.12 / versionCode 148 / io.github.fplus**。本文件用于维护发布流程，不把构建成功等同于全部功能真机验证。

## 一、版本与源码

- 核对 [app 构建配置](<../app/build.gradle>) 的 versionName、versionCode、applicationId。
- 核对 [随包版本](<../app/src/main/assets/version>) 与 [模块更新日志](<../app/src/main/assets/update.txt>)。
- 更新 [CHANGELOG](<../CHANGELOG.md>)、[项目首页](<../README.md>)、[发布说明](<发布说明-v1.3.12.md>)，新增功能与继承功能分开描述。
- [适配列表](<../app/src/main/assets/versions.json>) 只记录对应版本；没有真机结果时不扩大适配承诺。
- 修改 DexKit matcher 后递增 [初始化配置](<../core/src/main/java/io/github/fplus/core/hook/DouYinMain.kt>) 中的缓存版本，当前为 `33`。
- 检查 Git staged 文件，没有本地签名、口令、SDK 配置、缓存、APK、DEX、原始日志或无关工作区材料。

## 二、签名与固定发布包

- 沿用已发布证书，不重新生成维护线的签名。
- 密钥及本地签名配置由维护环境保存，不进入 Git 或源码归档。
- Release APK 核对包名、版本、证书与 ZIP 完整性。
- Debug 与 Release 使用不同签名，不互相覆盖安装。

## 三、构建与执行体

Windows / JDK 17 / SDK 34，已有依赖缓存时：

```powershell
.\gradlew.bat --offline --no-daemon --console=plain --max-workers=2 :core:testDebugUnitTest :app:assembleDebug :app:assembleRelease
```

- 42 项核心测试通过，失败 / 错误 / 跳过分别为 0。
- 核对 Xposed 入口 `io.github.fplus.HookInit` 与 `assets/xposed_init`。
- 核对 [R8 保留规则](<../app/proguard-rules.pro>) 中的入口、HighRefreshProvider、`beforeHookedMethod` / `afterHookedMethod`。
- 直接检查 Release DEX：应用侧与系统侧高刷回调存在且非空，参数改写、省电 / 热状态检查可达。
- PowerKeeper 分支必须在抖音插件、资源、MMKV、DexKit 初始化前返回。
- 完整 Lint、单元测试与真机结果分开记录，不能互相替代。

## 四、文档与真机口径

- 检查 README 和发布说明的下载链接、相对文档链接及代码围栏。
- 删除仅适用于维护工作区的绝对路径与过程叙述，不公开认证凭据。
- 区分“列表命中”“Hook 注册”“实际界面效果”“视频源帧数”。
- 说明高刷新率的主屏 / 主抖音 / 正常视频场景范围，保留省电与热限制。
- 尚未完成的 ROM、广告投放、重启持久性验证保持未验证状态。
- WebDAV 按媒体上传描述，不写成配置备份 / 恢复。

## 五、推送与发布

1. 检查远端 main 基准与目标版本标签，避免覆盖其他提交。
2. 创建发布提交；不强制推送，不改旧标签。
3. 创建 `v1.3.12` 标签并推送 main 和该标签。
4. 先准备 Release 草稿，上传固定签名 Release APK、Debug APK 与对应提交的源码 ZIP。
5. 验证每个附件名称、大小和 SHA-256；不静默删除同名不同内容的资产。
6. 发布 Release 并设为最新版本。
7. 重新读取 GitHub main、标签、README、Release 正文和附件元数据，核对提交与哈希。
